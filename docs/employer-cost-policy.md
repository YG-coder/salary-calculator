# 기업 총 인건비 조사·설계 (PR 5 사전 설계)

- 작성일: 2026-08-29
- 목적: 기업 총 인건비 계산기의 **정책 확정과 구조 설계**. 이 단계에서는 페이지를 구현하지 않는다.
- 결론 요약: **구현 가능. 단 산재보험료율은 사용자 입력이 필수**이며,
  기존 `calculators.ts`의 산재 0.7% 기본값은 **재사용하면 안 된다.**
  조사 중 **국민연금 요율이 2027년부터 매년 자동으로 틀려지는 구조**를 발견했다(아래 A-1).

> 자료 우선순위: ① 국가법령정보센터 법령 원문 → ② 소관 부처 고시 → ③ 기타 공공기관.

## A. 기존 코드 감사 — 먼저 고쳐야 할 것

### A-1. ⚠️ 국민연금 요율이 2027년부터 매년 틀려진다 (심각)

`src/lib/constants.ts:19`

```ts
nationalPension: 0.0475,   // "2026년 고시: 4.75%"
```

**이 값 자체는 2026년 기준으로 정확하다.** 그런데 근거가 "고시"가 아니라 **법률 부칙의
연도별 확정 스케줄**이다. 국민연금법 부칙 <법률 제20903호, 2025.4.2> 제4조 제1항은
사업장가입자의 기여금·부담금을 각각 다음과 같이 **미리 정해 두었다.**

| 연도 | 기여금·부담금 각각 | 합계 |
|---|---|---|
| 2026 | 1만분의 475 = **4.75%** | 9.5% |
| 2027 | 1만분의 500 = 5.00% | 10.0% |
| 2028 | 1만분의 525 = 5.25% | 10.5% |
| 2029 | 1만분의 550 = 5.50% | 11.0% |
| 2030 | 1만분의 575 = 5.75% | 11.5% |
| 2031 | 1만분의 600 = 6.00% | 12.0% |
| 2032 | 1만분의 625 = 6.25% | 12.5% |
| 2033~ | 제88조 제3항 본칙 **6.5%** | 13.0% |

즉 **2027년 1월 1일이 되는 순간 이 사이트의 모든 국민연금 계산이 틀린 값을 내놓는다.**
지금은 상수 하나에 올해 값만 박혀 있어, 사람이 매년 기억해서 고쳐야 한다.

**권고**: 이미 같은 문제를 겪고 해결한 선례가 이 저장소에 있다. `PENSION_LIMIT_PERIODS`와
`getPensionLimits(date)`가 기준소득월액 상·하한을 **적용 시작일 배열**로 관리한다.
국민연금 요율도 동일하게 **법정 스케줄 배열 + 조회 함수**로 바꾸고, 스케줄이 끝나는
2033년 이후는 본칙 6.5%로 떨어지게 한다.

⚠️ 이는 PR 5 범위(설계)를 넘어 **기존 계산 결과를 바꾸는 변경**이다. 2026년 값은 동일하므로
지금 당장 화면 결과는 바뀌지 않지만, 별도 PR로 분리해 회귀 테스트와 함께 처리해야 한다.

### A-2. 산재보험 0.7% 임의 기본값

`src/lib/calculators.ts:66-67`

```ts
// 산재보험 (사업주 전액 부담, 업종별 상이 → 평균값 0.7% 사용)
const industrialAccident = floor10(monthlyTaxable * 0.007)
```

- 근거 없는 **하드코딩된 평균값**이다. 상수 파일에도 없고 함수 안에 직접 박혀 있다.
- 보험료징수법 제14조 제3항에 따라 산재보험료율은 **사업 종류별로 고용노동부령**으로 정한다.
  같은 법 제14조 제5항은 특정 업종 요율이 전체 평균의 **20배**를 넘지 않도록 할 뿐이다.
  즉 업종 간 격차가 최대 20배까지 벌어질 수 있는 값이다.
- 4대보험 계산기 화면(`social-insurance-calculator/page.tsx:155, 162`)은 "약 0.7%",
  "평균값(0.7%)을 사용합니다"라고 **정직하게 밝히고는 있다.** 그러나 같은 페이지
  `:273`은 "업종별 0.7%~18%"라고 적어 놓았다. 최대 18%인 값을 0.7%로 계산해 놓고
  사업주 총부담을 제시하는 것은 총 인건비 맥락에서는 오차가 너무 크다.

**권고**: 기업 총 인건비 계산기는 산재보험료율을 **사용자 입력 필수 항목**으로 둔다.
기본값을 넣지 않는다. 기존 4대보험 계산기의 0.7%는 이번 PR에서 건드리지 않되,
`unsupported`로 기록하고 별도 판단 대상으로 남긴다.

### A-3. 사업주 고용보험 요율 기본값 — 구조는 적절

`src/lib/calculators.ts:49`에 `employerEmploymentRate = 0.0115` 기본값이 있으나,
화면(`social-insurance-calculator/page.tsx:28-33`)이 **사업장 규모 4단계를 선택하게**
하고 있어 사용자가 자기 사업장 값을 고를 수 있다. 구조 자체는 문제없다.

다만 이 4단계 값(1.15 / 1.35 / 1.55 / 1.75%)은 페이지 컴포넌트에만 있고 상수 파일에 없다.
총 인건비 계산기가 같은 값을 쓰려면 **정책 상수로 승격**해야 중복이 생기지 않는다
(PR 1에서 연차 정책 상수에 적용한 것과 같은 원칙).

## B. 사업주 부담 구조 (법령 원문 기준)

### B-1. 국민연금 — 노사 각각 동일 금액

국민연금법 제88조 제3항:

> 사업장가입자의 연금보험료 중 **기여금은 사업장가입자 본인이, 부담금은 사용자가** 각각
> 부담하되, 그 금액은 각각 기준소득월액의 1천분의 65에 해당하는 금액으로 한다.

부칙 제4조의 연도별 특례가 우선한다(A-1 표). **기준소득월액 상·하한이 적용**되므로
고소득 구간에서는 사업주 부담도 상한에서 멈춘다.

### B-2. 건강보험 — 노사 각각 50%

국민건강보험법 제76조 제1항:

> 직장가입자의 보수월액보험료는 직장가입자와 … 사업주가 각각 보험료액의 **100분의 50**씩 부담한다.

⚠️ **사립학교 교원은 예외**다(본인 50 / 사용자 30 / 국가 20). 일반 기업 계산기의
대상이 아니므로 `unsupported`로 둔다.

⚠️ 제76조 제2항: **보수 외 소득월액보험료는 직장가입자가 부담한다.** 사업주 부담이 아니다.

### B-3. 장기요양보험 — 건강보험료에 연동

건강보험료를 기준으로 부과되므로 노사 부담 비율도 건강보험과 같다.
현재 코드(`calculators.ts:74`)도 `employerLongTerm = longTermCare`로 동일하게 처리한다.

### B-4. 고용보험 — 실업급여만 절반, 나머지는 사업주 전액

보험료징수법 제13조 제2항(근로자):

> 근로자가 부담하여야 하는 고용보험료는 자기의 보수총액에 … **실업급여의 보험료율의
> 2분의 1**을 곱한 금액으로 한다.

같은 조 제4항(사업주):

> 사업주가 부담하여야 하는 고용보험료는 … 개인별 보수총액에 다음 각 호를 각각 곱하여
> 산출한 각각의 금액을 합한 금액으로 한다.
> 1. **고용안정·직업능력개발사업의 보험료율**
> 2. **실업급여의 보험료율의 2분의 1**

즉 **고용안정·직업능력개발사업분은 사업주가 전액 부담**하고, 실업급여분만 노사가 절반씩
나눈다. 이 부분이 사업장 규모에 따라 달라지는 이유다.

⚠️ 제13조 제3항: **65세 이후 신규 고용된 자는 실업급여 보험료를 징수하지 않는다.**
(65세 전부터 피보험자격을 유지한 경우는 제외)

### B-5. 산재보험 — 사업주 전액, 업종별

보험료징수법 제13조 제5항:

> 사업주가 부담하여야 하는 **산재보험료**는 그 사업주가 경영하는 사업에 종사하는
> 근로자의 개인별 보수총액에 … 산재보험료율을 곱한 금액을 합한 금액으로 한다.

제14조 제3항: 산재보험료율은 **사업의 종류별로 구분하여 고용노동부령**으로 정한다.
제14조 제5항: 특정 업종 요율이 전체 평균의 **20배**를 초과하지 않도록 한다.
제14조 제4항: 보험관계 성립 후 3년이 지나지 않은 사업은 별도로 정한다.

→ **업종을 모르면 산재보험료를 계산할 수 없다.** 기본값을 넣으면 안 된다.

## C. 설계 — 근로자 실수령액과 사업주 총비용의 분리

로드맵의 핵심 요구사항은 "근로자 공제액을 사업주 비용으로 오인하지 않도록" 하는 것이다.
가장 흔한 오해는 두 가지다.

1. **"4대보험 회사가 반 내주니까 내 월급의 9%가 회사 비용"** → 아니다. 사업주 부담은
   근로자 공제액과 **금액이 다르다**(고용보험 고용안정분, 산재보험 전액이 추가된다).
2. **"총 인건비 = 연봉"** → 아니다. 연봉 위에 사업주 부담분이 얹힌다.

### C-1. 결과 구조 (3단 분리)

화면을 **세 덩어리로 물리적으로 분리**하고, 세 값이 각각 무엇인지 한 줄로 못 박는다.

```
① 근로자가 받는 돈        월 실수령액        (연봉에서 공제를 뺀 값)
   └ 근로자 부담 공제      국민연금·건강·장기요양·고용·소득세·지방소득세
② 계약상 급여             월 세전 급여        (= ① + 근로자 부담 공제)
③ 회사가 쓰는 돈          월 총 인건비        (= ② + 사업주 부담분)
   └ 사업주 부담분         국민연금·건강·장기요양·고용(고용안정 포함)·산재
```

**금지 사항**: 근로자 부담 공제와 사업주 부담분을 **한 표에 나란히 합산**해서 "4대보험
총액"처럼 보여주지 않는다. 두 값은 부담 주체가 다르므로 더하면 의미가 없다.

### C-2. 오인 방지 문구 (설계 확정)

| 위치 | 문구 |
|---|---|
| ② 옆 | "근로자가 부담하는 공제액입니다. **회사 비용이 아닙니다.**" |
| ③ 옆 | "계약 연봉에 **추가로** 회사가 부담하는 금액입니다." |
| 산재 입력 | "업종별로 최대 20배까지 차이가 납니다. 사업장의 실제 요율을 입력하세요." |
| 결과 하단 | "퇴직급여 충당, 4대보험 외 복리후생비, 채용·교육비는 포함하지 않았습니다." |

### C-3. 입력 설계

| 입력 | 필수 | 기본값 |
|---|---|---|
| 연봉 또는 월 세전 급여 | ✅ | 없음 |
| 월 비과세 금액 | | 0 |
| 공제대상가족 수 · 8~20세 자녀 수 | | 1 / 0 |
| 사업장 규모 (고용보험 고용안정분 요율) | ✅ | **선택 강제** — 기존 4단계 재사용 |
| **산재보험료율** | ✅ | **기본값 없음. 사용자 입력** |

산재보험료율은 입력하지 않으면 **총 인건비를 계산하지 않는다.** 임의값으로 채워
숫자를 보여주는 것보다, 계산을 막고 근로복지공단에서 확인하도록 안내하는 편이 정확하다.

### C-4. 재사용

- `calculateSocialInsurance()` (`src/lib/calculators.ts`) — 이미 `totalEmployer`,
  `employerPension/Health/LongTerm/Employment`, `industrialAccident`를 반환한다.
  **산재 요율만 입력으로 받도록 확장**하면 총 인건비 계산에 그대로 쓸 수 있다.
- `calculateSalary()` (`src/lib/salary.ts`) — 근로자 실수령액
- 세금·보험 산식을 **복제하지 않는다** (PR 2에서 확립한 원칙)

| 10 | 기존 4대보험 계산기의 산재 0.7% 유지 여부 | A-2 참조. 이번 PR 범위 밖. 별도 판단 필요 |

## E. 다음 단계 제안

이 설계로 **구현 가능성이 확인되었다.** 다만 착수 순서에 주의가 필요하다.

1. ✅ **선행 PR — 국민연금 요율 스케줄화 (A-1) 완료.** `PENSION_RATE_PERIODS`와
   `getPensionRate(date)`를 추가하고, 2025~2033년 법정 경계·2026년 기존 결과·한국시간
   1월 1일 전환을 회귀 테스트로 고정했다. 후속 검토에서 표시 계층도 같은 조회 함수로
   통일하고, 고정 4.75% 문구가 재등장하면 실패하는 테스트를 추가했다.
2. **정책 상수 승격** — 사업장 규모별 고용보험 요율 4단계를 페이지에서 상수 파일로 이동.
3. **`calculateSocialInsurance()` 확장** — 산재 요율을 입력으로 받도록. 기본값을 두되
   총 인건비 계산기에서는 입력을 강제한다.
4. **총 인건비 계산기 구현** — C절 구조대로.

**PR 5 조사 단계에서는 코드를 작성하지 않았다.** 이후 별도 후속 커밋에서 1번을 완료했다.
