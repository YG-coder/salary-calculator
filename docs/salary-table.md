## 구현

- `src/lib/salaryTable.ts`: `SALARY_AMOUNTS_MAN`과 `buildSalaryPageData`로 행을 만든다. 연봉 목록·산식·기준일을 복제하지 않는다. 금액은 계산 결과의 숫자를 그대로 쓰며 표시 문자열에서 역산하지 않는다.
- `src/lib/salaryPageData.ts`: 상세 페이지가 쓰던 고정 조건을 `SALARY_PAGE_CONDITIONS`(비과세 0원, 공제대상가족 1명, 8~20세 자녀 0명, 원천징수 100%)로 이름 붙여 내보내고, 상세 페이지 계산이 이 값을 쓰게 했다. 자녀 0명·100%는 기존 기본값과 같아 상세 페이지 결과는 바뀌지 않는다. 표의 조건 안내 문구도 이 값에서 만든다.
- `src/app/salary-table/page.tsx`: 서버 컴포넌트. 기준 기간(`TAX_YEAR_AS_OF_LABEL`), 계산 조건, 참고표 안내, 실수령액 계산기 링크, 표, 유의사항.
- 열 순서는 연봉 · 월 실수령액 · 월 세전 급여 · 월 총 공제액이다. 좁은 화면에서 가장 중요한 월 실수령액이 스크롤 없이 보이도록 연봉 옆에 두었다. 표가 넓으면 표 영역 안에서만 가로 스크롤한다.
- 연봉 표시는 1억원 이상을 억 단위로 쓴다(예: 1억 5,000만원). 링크 대상 상세 페이지의 제목은 기존대로 "15,000만원" 표기다.
- 진입 경로: 홈의 연봉별 표 아래 버튼, 대표 연봉 링크 영역(실수령액 계산기와 연봉별 상세 페이지에 공통 표시)의 문장 링크.
- 사이트맵: `REFERENCE_ROUTES`를 새로 두어 `/salary-table`만 추가했다. 헤더·푸터·홈 카드를 강제하는 `CALCULATOR_ROUTES`에는 넣지 않았다(계산기가 아닌 참고표).

## 유지한 정책과 알아둘 점

- 연봉별 상세 페이지 27개의 사이트맵 제외·색인 정책은 바꾸지 않았다.
- 다만 사이트맵에 들어가는 새 표가 27개 상세 페이지로 링크한다. 실수령액 계산기의 대표 연봉 링크가 이미 20개를 링크하고 있었으므로 새로운 종류의 연결은 아니지만, 사이트맵 페이지에서 상세 페이지로 가는 내부 링크가 27개로 늘어난다는 점은 색인 정책을 다시 볼 때 고려해야 한다.
- 홈에서는 기존 규칙대로 `/salary/[amount]`로 직접 링크하지 않는다. 홈에 추가한 링크는 `/salary-table`이다.
- 이 페이지가 검색 순위나 유입을 높인다고 보장하지 않는다.

## Codex macOS 후속 검증 (2026-11-17, AI 확인)

`4788276`에서 전체 테스트, 타입 검사, 저장소 전체 린트를 실행해 통과했다. `npx next build --webpack` 및 `node scripts/check-site-urls.mjs`도 통과했다. 새 표는 정적 페이지로 생성되고 사이트맵에 포함되며 canonical/origin·공유 이미지·큰 카드·robots·JSON-LD 검사를 통과했다. 기본 Turbopack 빌드는 이번에 실행하지 않았다.

실제 빌드 화면에서 두 가지를 최소 수정했다.

- 브라우저 제목이 `2026년 연봉 실수령액 표 | 연봉계산기.kr | 연봉계산기.kr`로 중복됐다. 페이지 제목에서 사이트명을 제거하고 기존 layout의 제목 템플릿에 맡겼다. 공통 metadataBase·공유 메타데이터 함수는 유지했다.
- 공통 layout 안에 이미 main이 있으므로 새 페이지의 main을 일반 div로 변경했다. 최종 DOM의 main이 하나인 것을 확인했다. 기존 다른 페이지의 구조는 이번 범위에서 수정하지 않았다.

두 수정에 대한 회귀 검사를 기존 표 테스트에 추가했다. 수정 후 표 테스트·변경 파일 린트와 webpack 빌드(타입 검사 포함)·빌드 산출물 검사를 다시 통과했다. 계산 코드·열 순서·사이트맵 정책은 변경하지 않았다.
