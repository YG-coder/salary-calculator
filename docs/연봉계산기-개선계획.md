### 제공 정보

| 항목 | 내용 |
|---|---|
| 실수령액 차이 | 월·연 차이 (B − A), 부호 포함 |
| 공제 항목별 차이 | 국민연금·건강보험·장기요양보험·고용보험·소득세·지방소득세 각각의 A·B 값과 월·연 차액 |
| 한계 실수령률 | (연 실수령 차이) ÷ (세전 연봉 차이). 한계 공제율(1 − 한계 실수령률) 함께 표시 |
| 평균 실수령률 | A·B 각각 (연 실수령 ÷ 세전 연봉). 한계율과 다른 값임을 명시 |
| 비단조 구간 안내 | 두 조건 사이에 국민연금 상한 또는 간이세액표 조견표 상한이 끼면 경고 표시 |

### ⚠️ 실수령률 비단조성 (실측)

"연봉이 오르면 실수령률은 계속 떨어진다"는 통념은 사실이 아니다. 국민연금 기준소득월액
상한을 넘으면 보험료가 더 늘지 않아 한계 실수령률이 **오히려 올라간다.**

2026-08-29 기준(월 비과세 20만원·공제대상가족 1명), 국민연금 상한 도달 연봉은 약 **8,148만원**:

| 구간 | 한계 실수령률 | 국민연금 월 차액 |
|---|---|---|
| 8,000만 → 8,100만 | 66.32% | +3,960원 |
| 8,100만 → 8,200만 | 68.81% | +1,900원 (상한 걸침) |
| 8,200만 → 8,300만 | **71.09%** | **0원** (상한 도달) |

3,000만~1억 3,000만원을 100만원 단위로 훑으면 100개 구간 중 **40개**에서 한계 실수령률이
상승한다(국민연금 상한 + 간이세액표 조견표의 계단 구조). 이 값들은 테스트로 고정되어 있다.

### 범위 경계

기존 페이지의 내비게이션(`Header.tsx`, 홈 카드)에는 **추가하지 않았다.** 도구 간 상호 링크와
설명 보강은 PR 3의 범위이기 때문이다. 새 페이지에서 기존 계산기로 나가는 링크만 넣었다.

### 검증

- `npm test` 137건 통과 (연차 106 + 비교 31)
- 회귀: 5개 연봉 조건에서 `compareSalaries()` 결과가 `calculateSalary()`와 **객체 전체 일치**
- 항등식: 항목별 월 차액 합 + 월 실수령 차액 = 월 세전 차액
- 타입 검사·린트·프로덕션 빌드(44 페이지) 통과
- Playwright 브라우저 검증 30건 통과 (기존 계산기와 화면 값 대조, 비단조 안내, 390px 모바일 포함)

### 원 요구사항

- A 조건과 B 조건의 월·연 실수령액 차이를 제공한다.
- 국민연금, 건강보험, 장기요양보험, 고용보험과 소득세 차이를 제공한다.

- 동일 입력에서 기존 연봉 계산기와 결과가 일치하는지 회귀 테스트한다.
- 국민연금 상한 등으로 실수령률이 단조 감소하지 않는 구간을 반영한다.

## PR 3 — 협상 도구 정리 ✅ 완료·배포

### 배경

PR 2 완료 후 확인해 보니 **연봉↔실수령 도구 두 개가 모두 내비게이션에서 빠져 있었다.**
`/salary-comparison-calculator`는 신규라 그렇다 치더라도, `/target-salary-calculator`는
이미 배포된 상태에서 헤더·푸터·홈 어디에도 없이 RelatedCalculators 링크로만 도달
가능했다. sitemap에는 들어 있어 검색으로는 닿지만 사이트 안에서는 사실상 숨은 페이지였다.

따라서 PR 3은 "링크 보강"이 아니라 **두 도구를 사이트 구조에 편입시키는 작업**이 되었다.
로드맵 지침대로 신규 페이지는 만들지 않았다.

### 구현 결과

1. **역산 계산기 진입 경로 3곳 추가** — 홈 계산기 카드, 상단 `더보기` 메뉴, 푸터.
   (비교 계산기의 진입 경로는 `a26839f`에서 이미 추가됨)
2. **`src/components/calculator/ToolPicker.tsx` (신규)** — 연봉 계산기 3종의 역할 구분을
   한 곳에서만 정의하고 비교·역산 페이지에 삽입한다. 같은 설명을 두 페이지에 복사하면
   문구가 갈라지므로 단일 출처로 두었다. 현재 보고 있는 도구는 링크 대신
   "지금 보는 계산기" 배지로 표시한다.
3. **상호 링크** — 역산 → 비교 링크 추가(기존에는 비교 → 역산 한 방향만 있었다).
4. **비교 페이지 가이드 보강** — "받고 싶은 실수령액이 먼저 정해져 있다면 역산 계산기"
   문단 추가.

### 세 도구의 역할 (ToolPicker 단일 출처)

| 도구 | 답하는 질문 | 입력 | 결과 |
|---|---|---|---|
| 연봉 실수령액 계산기 | 이 연봉이면 실제로 얼마나 받나? | 세전 연봉 | 월 실수령액과 공제 내역 |
| 연봉 비교 계산기 | **연봉이 바뀌면 실수령액이 얼마나 달라지나?** | 연봉 두 개 (A·B) | 실수령액 차이와 한계 실수령률 |
| 목표 실수령액 역산 계산기 | **원하는 실수령액을 받으려면 연봉이 얼마여야 하나?** | 목표 월 실수령액 | 필요한 최소 세전 연봉 |

셋 다 같은 계산 엔진을 쓰므로 같은 조건에서 결과가 어긋나지 않는다.

### 재발 방지

`src/lib/__tests__/navigation.test.ts` (신규, 37건) — `CALCULATOR_ROUTES`의 **모든** 경로가
헤더·푸터·홈 카드에 존재하는지 검증한다. 라우트만 등록하고 진입 경로를 빠뜨리면
테스트가 깨진다. 푸터에서 역산 계산기를 지우고 실제로 실패하는지도 확인했다.
중복 링크, ROUTES에 없는 경로, ToolPicker 역할 정의의 일관성도 함께 검증한다.

### 검증

- `npm test` 174건 통과 (연차 106 + 비교 31 + 내비게이션 37)
- 타입 검사·린트·프로덕션 빌드(44 페이지) 통과 — **신규 페이지 없음**
- Playwright 27건 통과: 홈 카드 클릭 도달, 더보기 메뉴, 푸터 9종 전부, 역산↔비교 양방향
  클릭 도달, 자기 자신 링크 없음, sitemap 항목 수 불변(13개), 390px 모바일

### 원 요구사항

- 협상 관련 새 페이지를 성급히 만들지 않는다.
- 연봉 비교 계산기와 목표 실수령액 역산 계산기로 역할이 나뉘면 새 계산기를 만들지 않는다.
- 두 도구 사이의 설명과 상호 링크를 보강하는 수준에서 마무리한다.
- 독립적인 검색 의도와 사용자 가치가 확인될 때만 신규 페이지를 재검토한다.

## PR 5 — 기업 총 인건비 사전 설계

- 근로자 실수령액과 사업주 총비용을 명확히 분리한다.
- 근로자 공제액을 사업주 비용으로 오인하지 않도록 결과 구조와 문구를 설계한다.
- 국민연금·건강보험·장기요양보험·고용보험의 사업주 부담분을 구분한다.
- 산재보험처럼 업종별로 달라지는 요율에 임의 기본값을 넣지 않는다.
- 업종별 요율이 필요한 경우 사용자가 직접 입력하도록 설계한다.
- 정책을 확정하기 전에는 계산기 페이지를 구현하지 않는다.

### 현재 코드와의 충돌 점검

현재 `src/lib/calculators.ts`의 4대보험 계산에는 산재보험 평균 0.7% 기본값이 들어 있고 사업주 고용보험 요율에도 기본값이 설정돼 있다. PR 5에서 새 기업 총 인건비 계산기를 설계할 때 이 값을 그대로 재사용하면 안 된다. 기존 4대보험 계산기의 기본값 처리도 PR 5 조사 단계에서 별도로 감사한다.

## 유지되는 보류 사항

### `/salary/[amount]` 페이지

- 2,000만 원부터 1억 5,000만 원까지 500만 원 간격의 27개 페이지는 유지한다.
- sitemap 제외 상태를 유지한다.
- 근접 중복 감소, doorway 페이지가 아닌 독립적 가치, 운영자 결정이 모두 확인돼야 sitemap 복귀를 검토한다.
- `noindex` 여부나 sitemap 복귀를 다른 PR에서 부수적으로 변경하지 않는다.

### AdSense

- AdSense 재심 결과는 코드 밖의 외부 상태로 취급한다.
- 재심 승인 또는 반려를 코드 작업의 전제조건으로 두지 않는다.

## 작업 방식 (지난 세션에서 확립)

1. **정본 문서 하나를 계속 갱신한다.** 사본을 만들지 않는다. 상태가 바뀌면
   ① 저장소 `docs/` 정본 ② claude.ai 프로젝트 미러 ③ 대화창 전달 파일을 한 번에 맞춘다.
   문서를 새로 만들면 반드시 `docs/`에 저장하고 커밋한다.
2. **패키지 설치는 macOS에서 한다.** 리눅스 VM 쉘에서 `npm install`을 돌리면 darwin-arm64
   선택 의존성이 빠져 맥에서 `Cannot find module @rollup/rollup-darwin-arm64`로 테스트가 죽는다.
3. **소수 정밀도 테스트에는 0.1·0.05 단위를 포함한다.** 0.5·0.25는 이진 분수라 절대
   실패하지 않는다 (PR 1에서 이 함정 때문에 1원 손실 버그를 놓쳤다).
4. **1차 자료 우선.** 국가법령정보센터 → 법제처 법령해석 → 소관 부처 공식 자료 순.
   블로그·노무법인 글만으로 계산 정책을 확정하지 않는다.
