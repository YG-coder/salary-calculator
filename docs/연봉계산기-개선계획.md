### ⚠️ 실수령률 비단조성 (실측)

"연봉이 오르면 실수령률은 계속 떨어진다"는 통념은 사실이 아니다. 국민연금 기준소득월액
상한을 넘으면 보험료가 더 늘지 않아 한계 실수령률이 **오히려 올라간다.**

2026-08-29 기준(월 비과세 20만원·공제대상가족 1명), 국민연금 상한 도달 연봉은 약 **8,148만원**:

| 구간 | 한계 실수령률 | 국민연금 월 차액 |
|---|---|---|
| 8,000만 → 8,100만 | 66.32% | +3,960원 |
| 8,100만 → 8,200만 | 68.81% | +1,900원 (상한 걸침) |
| 8,200만 → 8,300만 | **71.09%** | **0원** (상한 도달) |

3,000만~1억 3,000만원을 100만원 단위로 훑으면 100개 구간 중 **40개**에서 한계 실수령률이
상승한다(국민연금 상한 + 간이세액표 조견표의 계단 구조). 이 값들은 테스트로 고정되어 있다.

## PR 3 — 협상 도구 정리 ✅ 완료·배포

### 배경

PR 2 완료 후 확인해 보니 **연봉↔실수령 도구 두 개가 모두 내비게이션에서 빠져 있었다.**
`/salary-comparison-calculator`는 신규라 그렇다 치더라도, `/target-salary-calculator`는
이미 배포된 상태에서 헤더·푸터·홈 어디에도 없이 RelatedCalculators 링크로만 도달
가능했다. sitemap에는 들어 있어 검색으로는 닿지만 사이트 안에서는 사실상 숨은 페이지였다.

따라서 PR 3은 "링크 보강"이 아니라 **두 도구를 사이트 구조에 편입시키는 작업**이 되었다.
로드맵 지침대로 신규 페이지는 만들지 않았다.

### 구현 결과

1. **역산 계산기 진입 경로 3곳 추가** — 홈 계산기 카드, 상단 `더보기` 메뉴, 푸터.
   (비교 계산기의 진입 경로는 `a26839f`에서 이미 추가됨)
2. **`src/components/calculator/ToolPicker.tsx` (신규)** — 연봉 계산기 3종의 역할 구분을

## PR 4 — 상여금 계산기 사전 조사 ✅ 조사 완료

조사 결과: **`docs/bonus-tax-policy.md`**

### 결론: 부분 구현 가능 — 단, 범위를 좁혀야 한다

**소득세 원천징수는 1차 자료로 산식이 확정된다.** 소득세법 제136조와 시행령 제195조가
지급대상기간 유무에 따른 계산 방법을 명시하고 있다.

```
월환산액 = (상여금 ÷ 지급대상기간 월수) + 지급대상기간의 상여 외 월평균 급여액
세액     = 간이세액표(월환산액) × 지급대상기간 월수 − 해당 기간 기납부세액
```

지급대상기간이 없으면 그 해 1월 1일(또는 직전 상여 지급월의 다음 달)부터 지급월까지를
지급대상기간으로 보고 같은 산식을 적용한다. 1년 초과는 1년으로, 1개월 미만 끝수는
1개월로 본다.

### ⚠️ 4대보험은 일반화 불가

이번 조사의 핵심 발견이다. **상여금을 받아도 그달 4대보험 공제액이 상여금에 비례해
늘어나지 않는다.**

| 보험 | 상여금 지급 달의 공제 증가 | 근거 |
|---|---|---|
| 국민연금 | **없음** — 기준소득월액은 미리 정해진 값이고 상·하한도 있다 | 국민연금법 제3조①5 |
| 건강보험 | **없음** — 보수월액 기준 부과 후 연말정산으로 사후 정산 | 국민건강보험법 제70조 |
| 장기요양보험 | **없음** — 건강보험료 대비 부과 | 위와 동일 |
| 고용보험 | **있음** — 지급 보수에 비례 | 보험료징수법 제2조③ |

상여금 하나로 "4대보험 전부 얼마 떼이나"를 보여주는 화면은 **틀린 값을 내놓게 된다.**
계산기를 만든다면 이름을 **"상여금 원천징수 계산기"** 로 한정하고, 국민연금·건강보험은
계산하지 않고 왜 이 달에 늘지 않는지 설명해야 한다.

### `unsupported` 6건

국민연금·건강보험·장기요양의 상여금분 추가 공제액, 건강보험 연말정산 추가 납부액,
기납부세액 자동 산정, 잉여금 처분 상여, 연말정산 후 최종 세부담,
성과급의 통상임금 해당 여부. 상세는 조사 문서 참조.

지급대상기간이 다른 상여를 같은 달에 여러 건 받는 경우는 `unsupported`가 아니다.
소득세법 시행령 제195조에 따라 각 지급대상기간 월수의 **산술평균**을 적용한다.

### 구현은 별도 PR

이 단계에서는 코드를 작성하지 않았다. 기존 `calcSimplifiedWithholdingTax()`를 재사용하며
세금·보험 산식을 복제하지 않는다.

### 원 요구사항

- 구현 전에 상여금 과세 방식 조사 문서를 작성한다.
- 국세청 등 1차 자료를 우선한다.
- 정기·비정기 상여금, 지급 주기와 원천징수 방식 등 필요한 정책 분기를 확인한다.
- 1차 자료로 계산 방식을 확정할 수 없는 조건은 `unsupported`로 명시하고 구현하지 않는다.
- 조사 결과로 구현 가능성이 확인된 뒤에만 별도 구현 PR을 계획한다.

## PR 5 — 기업 총 인건비 사전 설계 ✅ 설계 완료

설계 문서: **`docs/employer-cost-policy.md`**

### 결론: 구현 가능. 단 산재보험료율은 사용자 입력 필수

법령 근거를 모두 확정했다. 국민연금은 노사 각각 동일 금액(국민연금법 제88조③),
건강보험은 노사 각각 50%(건강보험법 제76조①), 고용보험은 **실업급여분만 노사 절반이고
고용안정·직업능력개발분은 사업주 전액**(보험료징수법 제13조②·④), 산재보험은 사업주
전액 부담(같은 법 제13조⑤)이다.

### ⚠️ 조사 중 발견한 별건 — 국민연금 요율이 2027년부터 자동으로 틀려진다

`constants.ts`의 `nationalPension: 0.0475`는 2026년 기준으로는 정확하다. 그런데 근거가
고시가 아니라 **법률 부칙의 연도별 확정 스케줄**이었다.
국민연금법 부칙 <법률 제20903호, 2025.4.2> 제4조는 2026년 4.75%부터 2032년 6.25%까지
매년 0.25%p씩 올리고 2033년부터 본칙 6.5%를 적용하도록 **이미 정해 두었다.**

| 2026 | 2027 | 2028 | 2029 | 2030 | 2031 | 2032 | 2033~ |
|---|---|---|---|---|---|---|---|
| 4.75% | 5.00% | 5.25% | 5.50% | 5.75% | 6.00% | 6.25% | 6.50% |

후속 작업에서 `PENSION_RATE_PERIODS`와 `getPensionRate(date)`를 추가해 해결했다.
계산·화면·JSON-LD가 같은 정책 조회 함수를 사용하고, 한국시간 연도 경계와 고정 요율
문구 재등장을 회귀 테스트로 막는다.

### 산재보험 0.7% 기본값 문제

`calculators.ts:67`의 `monthlyTaxable * 0.007`은 상수 파일에도 없이 함수에 직접 박힌
임의 평균값이다. 산재보험료율은 업종별 고용노동부령이고 특정 업종이 전체 평균의
**20배**까지 갈 수 있다(제14조⑤). 총 인건비 계산기는 이 값을 재사용하지 않고
**사용자 입력을 강제**하며, 입력이 없으면 계산하지 않는다.

### 결과 구조 3단 분리

근로자 공제액을 사업주 비용으로 오인하지 않도록 화면을 물리적으로 나눈다.

```
① 근로자가 받는 돈   월 실수령액
② 계약상 급여        월 세전 급여  (= ① + 근로자 부담 공제)
③ 회사가 쓰는 돈     월 총 인건비  (= ② + 사업주 부담분)
```

근로자 부담 공제와 사업주 부담분을 한 표에 합산해 "4대보험 총액"으로 보여주지 않는다.
부담 주체가 다르므로 더하면 의미가 없다.

### `unsupported` 10건

산재요율 기본값, 성립 3년 미만 사업장 요율, 출퇴근재해 요율, 퇴직급여 충당금,
사립학교 교원 건강보험 부담(본인50/사용자30/국가20), 65세 이후 신규 고용자 실업급여
면제, 두루누리 지원금, 장애인 고용부담금·임금채권보장기금, 복리후생비,
기존 4대보험 계산기의 0.7% 유지 여부. 상세는 설계 문서 참조.

### 후속 구현 순서

1. 사업장 규모별 고용보험 요율 4단계를 페이지에서 정책 상수로 승격
2. `calculateSocialInsurance()`가 산재 요율을 입력으로 받도록 확장
3. 총 인건비 계산기 구현

### 원 요구사항

- 근로자 실수령액과 사업주 총비용을 명확히 분리한다.
- 근로자 공제액을 사업주 비용으로 오인하지 않도록 결과 구조와 문구를 설계한다.
- 국민연금·건강보험·장기요양보험·고용보험의 사업주 부담분을 구분한다.
- 산재보험처럼 업종별로 달라지는 요율에 임의 기본값을 넣지 않는다.
- 업종별 요율이 필요한 경우 사용자가 직접 입력하도록 설계한다.
- 정책을 확정하기 전에는 계산기 페이지를 구현하지 않는다.

### 현재 코드와의 충돌 점검

현재 `src/lib/calculators.ts`의 4대보험 계산에는 산재보험 평균 0.7% 기본값이 들어 있고 사업주 고용보험 요율에도 기본값이 설정돼 있다. PR 5에서 새 기업 총 인건비 계산기를 설계할 때 이 값을 그대로 재사용하면 안 된다. 기존 4대보험 계산기의 기본값 처리도 PR 5 조사 단계에서 별도로 감사한다.

## 작업 방식 (지난 세션에서 확립)

1. **정본 문서 하나를 계속 갱신한다.** 사본을 만들지 않는다. 상태가 바뀌면
   ① 저장소 `docs/` 정본 ② claude.ai 프로젝트 미러 ③ 대화창 전달 파일을 한 번에 맞춘다.
   문서를 새로 만들면 반드시 `docs/`에 저장하고 커밋한다.
2. **패키지 설치는 macOS에서 한다.** 리눅스 VM 쉘에서 `npm install`을 돌리면 darwin-arm64
   선택 의존성이 빠져 맥에서 `Cannot find module @rollup/rollup-darwin-arm64`로 테스트가 죽는다.
3. **소수 정밀도 테스트에는 0.1·0.05 단위를 포함한다.** 0.5·0.25는 이진 분수라 절대
   실패하지 않는다 (PR 1에서 이 함정 때문에 1원 손실 버그를 놓쳤다).
4. **1차 자료 우선.** 국가법령정보센터 → 법제처 법령해석 → 소관 부처 공식 자료 순.
   블로그·노무법인 글만으로 계산 정책을 확정하지 않는다.
